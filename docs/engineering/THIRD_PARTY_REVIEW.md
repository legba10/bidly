# Third-party review ledger

**Review date:** 2026-08-20  
**Policy:** [`DEPENDENCY_POLICY.md`](../security/DEPENDENCY_POLICY.md)

This ledger records material bootstrap choices. Sources are official documentation, official organization repositories, or official registries. Repositories were inspected as upstream references only; none was cloned or copied into Bidly.

## Review method and limitations

For each material project the audit checked official ownership, latest release/activity, license, documented security policy/advisory path where exposed, compatibility, scripts/distribution path, and necessity. GitHub's aggregate open-issue count is not a critical-vulnerability count, and projects use incompatible labels. There was no honest, comparable “open critical issues” metric across all upstreams; this absence is recorded instead of presenting stars or issue totals as safety evidence. Current advisories and lockfile reachability scanners are release gates.

No known active compromise was identified from official project/security/release material during this point-in-time review. That is not a warranty; npm/action/binary provenance and advisories continue to change.

## Upstream repository snapshot

Official repositories explicitly requested for research were reviewed: `openai/codex` (Apache-2.0, `rust-v0.148.0` observed), `shadcn-ui/ui`, `radix-ui/primitives`, `microsoft/playwright`, `dequelabs/axe-core`, `OWASP/ASVS` (5.0.0), `OWASP/wstg` (stable 4.2; 5.0 under development), `gitleaks/gitleaks`, `google/osv-scanner`, `aquasecurity/trivy`, and `semgrep/semgrep`. All showed recent project activity at audit time; release cadence and repository security-policy exposure differ. Use tagged releases/advisories and the scanners, not aggregate stars/issues, for update decisions.
