# Bidly documentation map

Documentation is part of the product contract. Material changes to domain semantics, security boundaries, data residency, or selected foundations require the corresponding source-of-truth update and, where a trade-off is involved, an ADR.

- [`product/BIDLY_DOMAIN.md`](product/BIDLY_DOMAIN.md) — marketplace invariants and vocabulary
- [`architecture/`](architecture/) — system, data, scaling, recovery, cost, and ADRs
- [`engineering/`](engineering/) — environment, dependencies, quality gates, completion, and implementation evidence
- [`security/`](security/) — baseline, threat model, RBAC, abuse cases, and dependency policy
- [`design/`](design/) — product-design and token principles
- [`testing/`](testing/) — test strategy and coverage expectations

The documentation distinguishes implemented domain/schema foundations from ports and future operational products. “Future”, “planned”, “reserved”, and “target” statements are not claims that a control or feature already exists.
