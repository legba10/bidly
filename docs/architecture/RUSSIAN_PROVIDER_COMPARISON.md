# Russian infrastructure provider comparison

**Research date:** 2026-08-20  
**Scope:** architecture shortlist, not procurement or legal certification

Yandex Cloud, Selectel, and Cloud.ru all expose a plausible Russian deployment path for compute, managed PostgreSQL, Redis-compatible caching, S3-compatible storage, load balancing, registry, and infrastructure automation. Actual 152-FZ suitability belongs to the complete Bidly configuration, contract, access model, data flow, and operating practice; no provider badge makes the application compliant.

## Evidence and caveats

Official sources reviewed:

- Yandex Cloud: [Managed PostgreSQL](https://yandex.cloud/ru/docs/managed-postgresql/), [high availability](https://yandex.cloud/ru/docs/managed-postgresql/concepts/high-availability), [regions/zones](https://yandex.cloud/ru/docs/overview/concepts/region), [backups/PITR](https://yandex.cloud/ru/docs/managed-postgresql/concepts/backup), [Object Storage lifecycle](https://yandex.cloud/en/docs/storage/concepts/lifecycles), [Managed Valkey IaC](https://yandex.cloud/ru/docs/managed-valkey/tf-ref).
- Selectel: [cloud catalogue](https://selectel.ru/services/cloud/), [Terraform](https://docs.selectel.ru/terraform/), [managed databases](https://docs.selectel.ru/managed-databases/), [managed-DB SLA/topology](https://docs.selectel.ru/managed-databases/about/about-managed-databases/), [data centers](https://selectel.ru/about/data-centers/).
- Cloud.ru: [Evolution overview](https://cloud.ru/docs/evolution/overview/index), [product catalogue](https://cloud.ru/products), [PostgreSQL backups](https://cloud.ru/docs/paas-postgresql/ug/topics/guides__backups), [Object Storage IaC](https://cloud.ru/docs/terraform-evolution/ug/topics/reference/resources/cloudru_evolution_obs_bucket).

Public pages can change, and some SLA/pricing/processor facts live in negotiated contracts. Before selection, run a proof of concept and obtain written answers for payment, legal entity, physical locations/subprocessors, SLA exclusions/service credits, support, backup retention/restore, encryption/key control, quotas, egress, deletion, incident notice, and exit assistance.

## Recommendation

Keep all three in the procurement shortlist. Use Yandex Cloud only as the documentation/reference topology because its public managed-service and HA documentation is currently the most complete for this exercise; this is not a provider commitment. Prove the same OpenTofu module interfaces against at least one alternative before production selection.
